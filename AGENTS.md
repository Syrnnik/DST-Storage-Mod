# AGENTS.md

## Цель

Короткие рабочие правила для изменений в моде `Storage Viewer`

## Суть мода

- Мод добавляет в игру кнопку, которая открывает панель склада
- Панель показывает вещи на складе и их количество
- Складом считаются сундуки, возле которых в небольшом радиусе стоит табличка
- На табличке должно быть что-то нарисовано
- Текущая реализация в коде может отличаться, это допустимо и будет дорабатываться позже

## Структура проекта

- `src/modmain.lua` точка входа и подключение модулей
- `src/scripts/finder.lua` поиск сундуков, которые считаются складом
- `src/scripts/details.lua` сбор предметов и подсчет количества
- `src/scripts/actions.lua` кнопка в HUD, RPC и открытие панели
- `src/scripts/storagepanel.lua` UI панели склада
- `src/modinfo.lua` метаданные мода

## Ограничения

- Не использовать корневую папку `scripts/` как источник архитектурных решений
- Не редактировать корневую папку `scripts/` без явного запроса

## Принципы кода

- UI сущности в духе `StoragePanel` писать классом через `Class(Widget, ...)`
- Поведение и состояние панели держать в методах класса через `:` когда используется `self`
- Маленькие утилиты без состояния панели выносить в `local function`
- Публичное поведение панели оставлять методами класса, а вспомогательную логику скрывать в локальных функциях

## Проверки

- Основная команда проверки `just check`
- Если команду нельзя запустить, кратко указать причину и что проверено вместо нее

## GitHub

- Рабочая ветка по умолчанию `dev`
- Перед началом работы проверить `git status` и текущую ветку
- Перед пушем проверить staged diff и осмысленность коммита
- Пушить изменения напрямую в `dev`

## Типы коммитов

- `feat` новая функциональность
- `fix` исправление бага
- `refactor` изменения без изменения поведения
- `chore` изменения конфигов, сборки или зависимостей
- `test` изменения, связанные с тестами
- `style` только форматирование без изменения поведения
- `docs` только изменения в документации
- `ci` изменения CI-конфигурации

## Актуализация файла

- Периодически обновлять этот файл при изменениях в коде
- Обновлять при изменении структуры проекта, появлении новых файлов и изменении архитектуры мода
